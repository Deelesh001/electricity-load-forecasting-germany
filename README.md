# Germany Electricity Load Forecasting

This repository contains the complete data preparation, forecasting, and evaluation pipeline for short-term electricity load forecasting in Germany.

The project compares statistical, machine-learning, and deep-learning forecasting approaches using historical German electricity consumption together with historical weather information and calendar features.

The forecasting models include:

- Seasonal Naive
- Ridge Regression
- XGBoost
- Long Short-Term Memory (LSTM)
- Temporal Fusion Transformer (TFT)

## 1. Weather Data Collection

The first notebook is:

```text
notebooks/01_weather_data_collection.ipynb
```

Historical hourly weather data are collected using the Open-Meteo Historical Weather API with ERA5-Land data.

Weather data are collected for five German cities:

- Berlin
- Hamburg
- Cologne
- Frankfurt
- Munich

The following weather variables are retrieved:

- 2 m air temperature
- 2 m relative humidity

The city-level measurements are aggregated using an equal-weighted mean to create national weather proxy variables:

```text
temperature_mean
humidity_mean
```

The resulting hourly weather dataset is saved to:

```text
data/raw/weather/weather_germany_hourly_2015_2025.csv
```

All weather timestamps are stored in UTC.

---

## 2. Data Preprocessing

The second notebook is:

```text
notebooks/02_data_preprocessing.ipynb
```

German electricity consumption data are obtained from the SMARD.de Download Center:

https://www.smard.de/en/downloadcenter/download-market-data/

The data used in this project correspond to:

- Region: Germany (`DE`)
- Resolution: Hourly
- Data type: Actual electricity consumption
- File format: CSV

The two electricity-load files used are:

```text
Actual_consumption_201501010000_202501010000_Hour.csv
Actual_consumption_202501010000_202601010000_Hour.csv
```

Before running the preprocessing notebook, place both files inside:

```text
data/raw/load/
```

The preprocessing pipeline performs the following steps:

1. Loads the two SMARD electricity-consumption files.
2. Combines the electricity datasets.
3. Parses German local timestamps.
4. Handles daylight-saving-time transitions.
5. Converts electricity timestamps to UTC.
6. Loads the weather dataset generated by Notebook 01.
7. Merges electricity consumption and weather data.
8. Creates calendar features.
9. Checks for duplicate and missing observations.
10. Creates chronological training, validation, and test datasets.

Calendar features include:

```text
hour
day_of_week
is_weekend
month
is_holiday
```

The final dataset contains variables including:

```text
timestamp
load
temperature_mean
humidity_mean
hour
day_of_week
is_weekend
month
is_holiday
```

The chronological split is:

```text
Training:   2015–2023
Validation: 2024
Test:       2025
```

The processed datasets are saved to:

```text
data/processed/train.csv
data/processed/validation.csv
data/processed/test.csv
```

## 3. Forecasting Experiments

The third notebook is:

```text
notebooks/03_forecasting_experiments.ipynb
```

This notebook performs model training, forecasting, evaluation, and result generation.

The forecasting approaches evaluated are:

### Seasonal Naive

A simple time-series benchmark based on historical seasonal electricity-demand patterns.

### Ridge Regression

A regularized linear regression model used as a statistical and machine-learning baseline.

### XGBoost

A gradient-boosted decision-tree model capable of modelling nonlinear relationships between historical load, weather, and calendar variables.

### LSTM

A Long Short-Term Memory recurrent neural network designed to model temporal dependencies in sequential electricity-demand data.

### Temporal Fusion Transformer

A transformer-based forecasting architecture designed for multi-horizon time-series forecasting with historical covariates.

The forecasting models use a:

```text
168-hour historical lookback window
```

corresponding to the previous seven days of hourly observations.

---

## Weather Information

The experiment uses historical weather information as model covariates.

The weather variables used are:

```text
temperature_mean
humidity_mean
```

These variables are derived from historical ERA5-Land observations across the five selected German cities.

Only historical weather information available within the model input window is used.

Future realized weather values are not supplied to the forecasting models.

---

## Data Split

The experiment uses a chronological split to preserve the temporal structure of the forecasting problem.

```text
2015–2023  → Training
2024       → Validation
2025       → Test
```

The validation period is used for model development and hyperparameter selection.

The 2025 dataset remains held out for final model evaluation.

---

## Evaluation

Models are evaluated using the held-out 2025 test period.

The main forecasting metrics are:

```text
MAE
RMSE
MAPE
```

The experiments also include additional analyses such as:

- Model comparison
- Forecast-horizon analysis
- Weather-feature ablation
- Multi-seed evaluation
- Forecast visualizations

## Reproducibility

The repository separates data collection, preprocessing, model training, and evaluation into independent stages.

This allows the complete forecasting experiment to be reproduced from the original SMARD electricity-consumption data and Open-Meteo ERA5-Land weather data.
